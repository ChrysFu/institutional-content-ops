# Operations Runbook · 内容工作流运行手册

本手册用于自动预检、人工审阅、排期和发布环节发生异常时的快速处置。自动化结果从不构成发布授权。

## 1. 事件分级

| 级别 | 判定 | 响应目标 | 示例 |
|---|---|---|---|
| SEV-1 | 已发布内容可能造成合规、声誉或个人权益影响 | 立即响应 | 错误政策表述、未经授权的个人信息 |
| SEV-2 | 发布链路阻塞或内容存在重要事实错误，但尚未扩散 | 30 分钟内 | 终审后发现头衔、日期或数字变化 |
| SEV-3 | 自动检查、格式或非关键数据异常 | 下一个工作时段 | 策略 JSON 无效、内部链接缺失 |

## 2. 首次响应

1. 记录 `content_id`、revision、发现时间、发现人和当前状态；
2. 冻结排期与后续自动动作，避免扩大影响；
3. 保存批准版本、线上版本、预检结果和平台错误，不先覆盖证据；
4. 指定唯一事件负责人和沟通窗口；
5. 按下表选择恢复路径。

## 3. 恢复路径

| 场景 | 恢复动作 | 完成判据 |
|---|---|---|
| 预检返回退出码 1 | 根据 `issues` 修改草稿，递增 revision 后重新运行 | 新结果可进入人工审阅 |
| 预检返回退出码 2 | 修复路径、UTF-8 编码、策略 JSON 或写入权限 | 工具正常完成；禁止把异常当作通过 |
| 平台暂时不可用 | 使用同一幂等键指数退避，最多重试 3 次 | 只产生一次发布记录 |
| 批准后事实变化 | 取消原批准，回到事实核对和终审 | 新批准明确对应最新 revision |
| 已发布错误 | 负责人决定撤回、更正或补充说明，并保存前后版本 | 线上状态核验完成，相关方已通知 |

## 4. 回滚检查单

- 确认回滚对象和当前线上版本，避免撤回错误内容；
- 停止尚未执行的二次分发、定时任务和通知；
- 按平台能力撤回或替换，并记录无法完全撤回的渠道；
- 用独立设备或账号核验公众可见结果；
- 通知内容负责人、审批人和受影响相关方；
- 建立后续行动项，每项包含负责人和截止日期。

## 5. 事件关闭

关闭事件前必须记录根因、影响范围、发现方式、恢复时间线、是否需要更正说明，以及防止复发的流程或代码变化。SEV-1/2 应在五个工作日内完成复盘；复盘材料不得包含不必要的敏感信息。
